# 🏗️ System Analysis & Design

## Yaseer Operations Big Data Analytics Platform

---

## 🔹 System Architecture

The system follows a distributed data architecture:

1. **Data Source:** MariaDB (LIS System)
2. **CDC Layer:** Debezium captures changes
3. **Streaming Layer:** RabbitMQ handles messaging
4. **Storage Layer:** ClickHouse & MinIO
5. **Processing Layer:** Python ELT + dbt
6. **Orchestration:** Apache Airflow
7. **Visualization:** Metabase & Superset

---

## 🔄 Data Flow (ELT Process)

1. Capture database changes using Debezium
2. Send events to RabbitMQ
3. Consume data using Python loader
4. Store raw data in ClickHouse
5. Transform data using dbt
6. Serve analytics via dashboards

## 🧬 ERD (Textual Description)

Main Entities:

* **Patients** (PatientID, Name, Age, Gender)
* **Tests** (TestID, TestName, Category)
* **Orders** (OrderID, PatientID, Date)
* **Results** (ResultID, OrderID, TestID, Value)

### Relationships

* Patient → Orders (1:N)
* Order → Results (1:N)
* Test → Results (1:N)

## 🔧 Design Decisions

* Use ELT instead of ETL for scalability
* Use ClickHouse for high-performance analytics
* Use Airflow for workflow orchestration
* Use Medallion Architecture for data quality
